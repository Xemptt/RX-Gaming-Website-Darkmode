RX-GAMING WEBSITE

Run commands from this directory (the one containing package.json).
Requires Node.js 22 or newer supported LTS and npm.

LOCAL PREVIEW
  npm ci
  npm run dev
  Open http://localhost:3000

CONFIGURATION
Copy .env.example to .env.local and fill in your deployment values.
SITE_URL is the public website origin, not a Minecraft server address. Set it
before building and keep the same value when running: static metadata, robots
and sitemap URLs are generated at build time. Rebuild when changing domains.
For local development set SITE_URL=http://localhost:3000 or leave it unset.
TEBEX_PUBLIC_TOKEN is your store's Headless API public token.
The existing NEXT_PUBLIC_TEBEX_PUBLIC_TOKEN name is also supported.
TEBEX_PRIVATE_KEY is the Private Key from the same Tebex API Keys page. Set it
only as a server-side environment variable. Never use a NEXT_PUBLIC_ prefix
for the private key or commit its value to source control.

Checkout attaches the Minecraft Java username when creating the Tebex basket.
Backend baskets also send the real customer IP. Tebex requires HTTP Basic
authentication with the public token and private key for this IP override;
omitting authentication produces HTTP 422: Basic auth credentials are required.
Vercel provides the trusted customer IP header automatically. Other hosts must
set TEBEX_CLIENT_IP_HEADER to a header overwritten by their trusted reverse
proxy with one actual IPv4/IPv6 address, and block direct access to the app.
Local checkout needs the same trusted proxy setup. Without a private key or
trusted customer IP, visitors can use the official hosted Tebex store.
Set SITE_URL to your HTTPS public origin for production. Add both Tebex keys
to the Vercel Production environment before deploying the checkout fix.

VALIDATION
  npm test
  npm run typecheck
  npm run build
  npm audit

PRODUCTION
  npm run build
  npm start
Or use Dockerfile. Supply your public origin while building:
  docker build --build-arg SITE_URL=https://your-website.example -t rx-gaming .
This sets the same default SITE_URL in the runtime image. Supply the Tebex
keys and trusted proxy configuration when running the container. Do not put
tokens or secrets in build arguments. .env files and local node_modules are
excluded from the build context. Rebuild the image if the public origin changes.
The Docker image runs Next.js standalone output as a non-root user.

PAYMENTS AND STATUS
Catalog prices, currency and availability come from Tebex. Final taxes,
discounts, subscription terms and payment totals are confirmed by Tebex.
The return page cannot independently verify payment and does not clear carts.
Before enabling purchases on a new deployment, confirm payment, cancellation,
receipts and in-game delivery through the merchant's test/payment workflow.
Automated checkout tests use mocked Tebex responses and never charge money.
Server status uses mcsrvstat.us and may be cached for up to five minutes.

SALES AND DISCOUNT CODES
Manage sale prices and coupon eligibility in Tebex. The catalog reads current
Tebex prices and discount flags; sale badges and the announcement update when
the page opens, returns to the foreground, and every minute while visible.
The announcement endpoint can cache current sale status for up to one minute.
Coupon codes entered at checkout are always checked with Tebex, so new codes
do not require website edits or a redeploy. The Headless API does not provide
a public list of coupon codes, so private/restricted codes are not advertised
automatically. The public coupon advert is configured with announcementCoupon
in store-settings.json (currently RX-G); update or clear it when that campaign
changes. It is displayed independently of automatic package sale detection.
For a storewide coupon, check Engagement > Coupons > Effective On in Tebex
and any package exclusions. Tebex controls applicability and usage limits;
the website shows its rejection reason and cannot override those settings.

The old sample products.json is retained as source reference, not a catalog
or checkout fallback. Live numeric package IDs are revalidated server-side.

DISCORD RANK DELIVERY
Create an application in https://discord.com/developers/applications and open
OAuth2. Register this exact redirect for production:
  https://site.rx-gaming.online/api/discord/callback
Set DISCORD_CLIENT_ID and DISCORD_CLIENT_SECRET in Vercel Production environment
variables, then redeploy. Use the OAuth2 Client Secret, not a bot token. Never
commit the secret or use a NEXT_PUBLIC_ prefix. SITE_URL must match the origin
where customers connect (https://site.rx-gaming.online for this deployment).
Local development needs a separate registered http://localhost:3000/api/discord/callback
redirect and SITE_URL=http://localhost:3000. Preview domains need their own
registered redirect and matching SITE_URL; production credentials alone do not
register new preview URLs.

Buyers connect Discord from their cart, approve the identify permission, and
return to checkout with their cart, Minecraft username and voucher retained.
The site verifies the account with Discord and keeps a signed, HttpOnly account
cookie for 24 hours. OAuth tokens are not stored. Tebex receives the verified
Discord ID as package variable_data.discord_id; request-body IDs are ignored.
Disconnecting or changing accounts discards the prepared basket, not the cart.
Packages with Discord delivery require a connected account even if Tebex marks
the option optional, to avoid completing the order without the expected role.
Role assignment remains controlled by the package's Tebex Discord Actions and
the existing Tebex bot. The buyer must join the server; the bot needs Manage
Roles permission and a role above each rank role. No new bot is required.
